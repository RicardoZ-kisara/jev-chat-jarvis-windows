# 从 QQ 记录直接获得判断与回复

0.1.3 接通已导入会话到判断和回复的完整流程。无需复制近期消息，也无需等待全量长期档案生成。

## 使用

1. 在工作台选择「已导入的 QQ 会话」，搜索联系人或群号。会话按最后消息时间排序，界面显示近期消息、实际发送者和时间。
2. 可填写关系背景，再点击「分析可能性并生成回复」。也可在长期聊天档案中点击「分析此会话并给出回复」。只有点击分析才发起模型请求。
3. 查看意图、对方需求、建议动作、紧张程度及其他七题判断。展开「查看其他可能性」比较备选解释。
4. 查看三条不同策略的排序回复、各自理由和原文依据；点击 M 编号回查聊天，点击「复制」后自行决定是否发送。
5. 最新分析按会话保存在本机，再次打开自动恢复。新导入改变记录后，旧分析失效，需要重新分析。QQ 实时新消息需先通过「直接读取 QQ 记录」更新本地归档。

## 来源与分析范围

当前本机使用已登录的 ChatGPT/Codex。ChatGPT 按仓库原有 Jev 七题结构输出概率、解释和候选，**并非 Jev 模型本身的输出**。意图/动作/需求的百分比是各组备选解释的相对估计；三条回复的百分比是相对偏好，均未经校准，不代表对方真实心理或回复成功率。API 模式仍保留真实 Jev 接口及候选生成服务的独立配置。

直接会话分析取近期最多 40 条、约 12,000 字符，单条超过 4,000 字符会明确标记截断；完整原文仍可回查。保留群成员昵称、发送者方向、时间和多行正文，不把群成员对彼此的消息一概当作向本人提问。如果最近消息由本人发出，会提示候选仅供必要时跟进。

模型还会收到相关历史原文、有效的长期档案及检索到的分段记忆，并显示本次使用范围。尚未生成长期档案时，仍可用近期消息与相关原文分析；需要更完整的长期整理时，点击「查看 / 更新长期记忆」，分段处理全部记录。关键词检索并不保证找回所有相关事实，概率与摘要也不是事实认证。

分析按 `analyzedAt` 和消息时间区分现在与旧记录；用户应核对已经过去的安排。图片、语音等仅有占位时不推断内容。

## 保存与校验

最近一次分析、候选及其依据存入用户目录 `qq-history.sqlite` 的 `conversation_analyses` 表。按会话独立保存，记录版本变化后不再展示为有效结果。删除会话同时删除对应分析；清空工作台只清空当前界面。

模型数值需符合范围和概率总和，候选必须为三条不同回复；引用必须属于本次已提供的原文/长期档案范围。无法解析、缺少依据或引用越界会报错，不用假概率填补。验证引用编号只证明可回查，不证明模型理解正确。

开发验证：`npm test` 和显式运行 `node scripts/codex-smoke.cjs`。后者只使用隔离配置中的合成聊天，真实调用 ChatGPT，检查无需手工输入、七题结果、排序、原文回查、复制、刷新恢复和长期档案关联；不自动发送任何私人聊天。
