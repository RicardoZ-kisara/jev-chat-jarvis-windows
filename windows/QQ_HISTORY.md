# QQ 历史导入与长上下文

## 支持的数据入口

首版支持可读导出文件，**不直接解析 QQ NT 原始数据库，不自动从 Tencent Files 中抽取历史**。已有 QQ JSON/TXT 导出可以直接尝试；不认识的格式会报错，不会假装导入成功。导入只在本机进行。

每个导出文件只应包含一个联系人或一个群聊。界面中填写会话名称和本人 QQ 号；增量导入时选择已有会话，本人 QQ 号不能改变。单文件上限 50 MB、250,000 条文字消息；超过上限请按日期拆分并导入同一会话。附件、空正文跳过并统计；不对图片、语音和视频的内容做推断。

### JSON

支持消息数组，或者含 `messages` 数组的对象。可接受 ChatLab 格式中的 QQ 文本消息字段；不是完整 ChatLab 格式实现，不导入附件或其他聊天平台。支持字段：

| 字段 | 要求 |
| --- | --- |
| `sender`，或 `from` | 发送者 QQ 号或稳定标识；必填 |
| `content`，或 `text` | 文字消息；必填 |
| `timestamp`，或 `time` | Unix 秒/毫秒数，或可解析的日期字符串；必填 |
| `platformMessageId`，或 `id` | 可选，原消息唯一 ID；优先用于去重 |
| `senderName` / `accountName` | 可选，显示昵称 |

```json
{
  "meta": {"platform": "qq", "ownerId": "100001"},
  "messages": [
    {"id": "m1", "sender": "100002", "timestamp": "2026-09-01T10:00:00+08:00", "content": "周五前把修改稿给我可以吗？"},
    {"id": "m2", "sender": "100001", "timestamp": "2026-09-01T10:01:00+08:00", "content": "可以，我周四整理。"}
  ]
}
```

可直接试用 [示例文件](examples/qq-history.json)，本人 QQ 号填 `100001`。其中内容、账号均为虚构测试数据。

### TXT

文件编码为 UTF-8，支持以下常见导出布局：

```text
2026-09-01 10:00:00 同学(100002)
周五前把修改稿给我可以吗？

2026-09-01 10:01:00 我(100001)
可以，我周四整理。
```

消息正文可以多行。无时区的 TXT 时间按本机时区解释；跨时区历史请优先使用带时区的 JSON。没有日期或发送者的自由文本不作为历史导入，仍可放到即时对话输入框分析。

## 从长期记录到回复

1. **独立会话与去重**：有原消息 ID 时按 ID 去重；否则按时间、发送者和完整正文哈希去重。同秒同人相同正文可能被合并，导出含原始 ID 时更可靠。ID 相同但正文变化时保留第一次导入内容，不自动改写历史。
2. **分段更新档案**：按时间排序，每段最多 100 条或约 12,000 字符（单条超长消息单独成段）。将前一份压缩档案与下一段原文交给生成模型，更新关系观察、事件、待办。每个成功分段立即保存进度。
3. **依据可回查**：每项必须带 `M数字` 原文引用，程序校验其存在于同一会话、且在已处理范围中。点击编号查看时间、发送者和原文。编号有效不等于结论必然正确，需要自行核对语义。
4. **回复时选择相关历史**：中文二字词/英文词关键词匹配最多 16 条，另取最近 8 条，去重并限制到约 10,000 字符；附上有效档案和覆盖范围，再与当前最多 10 条即时对话一起请求模型。不使用未经计算的向量相似度，也不声称一次调用读了全库。

档案面向重点总结，提示模型每类最多 20 条、每条 120 字；原始消息仍保留在本机。特别长的会话中，较早的细节可能被压缩，当前关键词检索也不能保证命中所有语义相关内容。建议使用至少 32K 上下文的生成模型；上下文较小的模型可能拒绝请求。失败时保留上一个已完成分段。

## 暂停、更新与数据存储

相同会话、相同导入版本、相同模型时支持从已完成分段继续。新增历史导入会使档案过期，下次重建全会话，避免补录早期消息后沿用错误时间线。未完成的档案明确标注 `已覆盖条数/总条数`；旧档案不会用于新版本的辅助回复。

导入消息、昵称、QQ 号和模型档案存储在应用用户目录的 `qq-history.sqlite`，数据库为**本机明文**。API 密钥另用 Windows DPAPI 加密，不放在该数据库里。删除会话只删除助手中的副本，原始导出和 QQ 文件不变；SQLite 的正常删除并非磁盘安全擦除。

点击“生成 / 继续长期档案”才会分段调用模型；界面先展示消息数、字符数、最多请求次数及目标服务。点击“分析对话”并关联历史时，会把档案和选中的历史原文一起发送。只有使用本机模型、并关闭外部 Jev 判断时，相关模型请求才全部留在本机。

参考字段来源：[ChatLab 导入协议](https://docs.chatlab.fun/standard/chatlab-import)。
